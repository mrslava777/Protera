# PROTERA — сайт с личным кабинетом и админ-панелью (PHP + MySQL)

Готовый пакет для хостинга hb.by: каталог с карточками товаров, регистрация с подтверждением
e-mail, восстановление пароля, несколько адресов доставки, оформление заказа с зоной/интервалом/оплатой
и админ-панель, которая редактирует сайт и пишет журнал действий.

## Что внутри

```
index.html                 сайт (каталог, карточка товара, кабинет, оформление заказа)
.htaccess                  заголовки безопасности
api/                       публичный API и авторизация
  config.php               НАСТРОЙКИ: домен, БД, почта, ключ установки, пароль админа
  install.php              создание таблиц + стартовые данные (удалить после установки)
  site.php                 контент сайта: настройки, категории, товары, зоны, оплата
  register.php login.php logout.php me.php
  verify.php resend.php forgot.php reset.php reset_check.php
  addresses.php            адреса клиента (добавить/изменить/удалить/основной)
  orders.php               создание и история заказов
  profile.php password.php delete.php
admin/                     админ-панель
  login.php index.php orders.php order.php products.php product-edit.php
  categories.php delivery.php payments.php users.php settings.php log.php password.php
  assets/admin.css
uploads/products/          фото товаров (загрузка с устройства)
storage/                   логи (закрыт от веба)
```

## Требования

- PHP **8.0+** (рекомендуется 8.1–8.3), расширения: `pdo_mysql`, `mbstring`, `openssl`, `session`, **`gd`** (нужно для сжатия фото), `exif` (поворот фото с телефона).
- MySQL 5.7+ / MariaDB 10.3+.
- Права на запись в `uploads/products/` (и `storage/`, если включён `mail.driver = log`).

## Установка

1. **Загрузите архив** в корень сайта (`public_html`/`www` на hb.by — точное имя в разделе «Файлы»).
   `index.html` должен лежать рядом с папками `api/`, `admin/`, `uploads/`.
2. **Создайте базу MySQL** и пользователя с полными правами. Запишите хост, имя, логин, пароль.
3. **Заполните `api/config.php`**: `site_url` (без слэша), `db`, `mail`, `install_key`, `admin_password`.
4. **Создайте таблицы и демо-данные**: откройте `https://ваш-домен/api/install.php?key=ВАШ_КЛЮЧ`.
   Скрипт создаст таблицы, 12 товаров, категории, 3 зоны доставки, 3 способа оплаты, тексты сайта
   и администратора **admin** с паролем из `admin_password`.
5. **Удалите `api/install.php`**, смените `install_key`, смените пароль администратора в разделе «Пароль».
6. **Проверьте** регистрацию, письмо, вход, добавление адреса и заказ. Заказ сразу появится в админке.

## Админ-панель

Вход: `https://ваш-домен/admin/` → логин/пароль администратора.

| Раздел | Что редактируется |
|---|---|
| Обзор | заказы, суммы, клиенты, последние действия |
| Заказы | список с фильтрами, карточка заказа, смена статуса (Новый / Подтверждён / Доставлен / Отменён) |
| Товары | карточки: название, категория, цена, старое цена, объём, короткое и полное описание, плашка, иконка, порядок, публикация, **фото с устройства** |
| Категории | названия и коды фильтров каталога |
| Доставка | зоны, города зоны, интервалы (по одному в строке), примечание |
| Оплата | способы оплаты для оформления заказа |
| Клиенты | список, число заказов, сумма, адреса, подтверждение e-mail |
| Настройки сайта | заголовок и подзаголовок главного экрана, телефон, e-mail, зона, часы, тексты «О компании», подпись доставки, SEO title/description, копирайт |
| Журнал действий | кто, что, когда и с какого IP делал в панели |
| Пароль | смена пароля администратора |

Все изменения сразу видны на сайте. Каждое действие (вход, создание/изменение/удаление, смена статуса,
загрузка фото, смена пароля) пишется в `admin_log` и доступно в разделе «Журнал действий».

## Как работает заказ

1. Клиент добавляет товары в корзину (корзина хранится в браузере).
2. Нажимает «Оформить заказ» → выбирает сохранённый адрес (или добавляет новый).
3. Город адреса определяет зону доставки → показываются только интервалы этой зоны.
4. Выбирает способ оплаты из активных в админке.
5. Сервер проверяет адрес, зону, интервал, оплату и **сам считает сумму по ценам из БД**
   (подменить цену из браузера нельзя), создаёт заказ со статусом «Новый».
6. Заказ виден клиенту в «Заказах», администратору — в админ-панели.

## Адреса

Клиент хранит до нескольких адресов (до 10): название (Дом/Офис), город, улица и дом, квартира,
подъезд, этаж, комментарий, «основной». Города берутся из активных зон доставки — если города нет
в зонах, адрес с ним сохранить нельзя. Основной адрес подставляется при оформлении заказа.

## Загрузка фото и авто-сжатие

- Раздел «Товары» → «Изменить» → поле «Фото товара» → выбрать файл с устройства → «Сохранить».
- Поддерживаются JPG, PNG, WEBP, GIF **до 20 МБ**; файл проверяется как изображение.
- После загрузки фото автоматически сжимается: уменьшение до **1600×1600 px**, JPEG/WEBP
  перекодируются с качеством 82, PNG — с максимальной компрессией, поворот по EXIF для фото с телефона.
  GIF не перекодируется (чтобы не сломать анимацию).
- Админ видит результат в сообщении: «Фото сжато: 7,6 МБ → 625 КБ, размер 1600×1067 px».
- Настройки — в `api/config.php`, блок `uploads`: `max_mb`, `max_width`, `max_height`, `quality`.
- Файлы складываются в `uploads/products/`, имя генерируется случайно, старое фото удаляется.
- Если фото не загружено, на сайте показывается иконка товара.

Чтобы принимались файлы больше 2 МБ, поднимите лимиты PHP: в пакете есть `.user.ini`
(`upload_max_filesize = 20M`, `post_max_size = 25M`) — он работает на PHP-FPM/CGI. Если хостинг
его игнорирует, задайте те же значения в панели hb.by («Настройки PHP»). Иначе сервер отклонит
файл ещё до обработки, и в админке появится сообщение о превышении лимита.

## Настройка почты

### SMTP (рекомендуется)

```php
'mail' => [
    'driver'    => 'smtp',
    'from'      => 'no-reply@ваш-домен.by',
    'from_name' => 'PROTERA',
    'reply_to'  => 'info@ваш-домен.by',
    'smtp' => [
        'host'   => 'mail.ваш-домен.by', // сервер из справки хостинга
        'port'   => 465,                  // 465 = SSL, 587 = STARTTLS
        'secure' => 'ssl',                // ssl | tls | ''
        'user'   => 'no-reply@ваш-домен.by',
        'pass'   => 'пароль ящика',
    ],
],
```

### Встроенная `mail()`

```php
'driver' => 'mail',
'from'   => 'no-reply@ваш-домен.by',
```

Ящик `from` должен существовать на домене.

### Проверка без отправки

```php
'driver' => 'log',
```

Письма пишутся в `storage/mail.log` — удобно проверять ссылки подтверждения и сброса.

Для доставки в inbox: SPF + DKIM домена, отправка только с адреса домена, проверка на mail-tester.com.

## Безопасность

- Пароли клиентов и администратора — только `password_hash()` (bcrypt).
- Токены подтверждения/сброса — 32 случайных байта, в БД хранится SHA-256, одноразовые, TTL 24 ч / 1 ч.
- CSRF-токены для всех POST (сайт и админка), cookies `HttpOnly` + `SameSite=Lax` + `Secure` при HTTPS.
- Лимиты: вход 8 неудач / 15 мин, регистрация 5 / час с IP, письма 3 / час на адрес, вход в админку 6 / 15 мин.
- Загрузка изображений проверяется `getimagesize()`, в `uploads/` запрещено выполнение скриптов.
- После смены/сброса пароля старые сессии клиента перестают действовать.

## Частые проблемы

| Симптом | Причина / решение |
|---|---|
| «Сервер недоступен» | неверный путь к `api/`, сайт открыт как файл или PHP не выполняется |
| 500 на `api/*.php` | смотрите `error_log`; проверьте PHP 8+, `pdo_mysql`, синтаксис `.htaccess` |
| «База данных недоступна» | неверные `db.*` или база не создана |
| Письма не приходят | `mail.driver = log` → смотрите `storage/mail.log`; проверьте «Спам», SMTP-логин, SPF/DKIM |
| Ссылка ведёт на `example.by` | не заполнен `site_url` |
| Фото не загружается | права на `uploads/products/`, файл больше 20 МБ, лимиты `upload_max_filesize`/`post_max_size` |
| Не открывается админка | удалён ли `admin/`; вход `admin` + пароль из `admin_password` |
| 419 «Сессия устарела» | истекла сессия — обновите страницу |

Локальная проверка: `php -S 127.0.0.1:8000` в корне пакета, в конфиге `db.driver = sqlite`,
`site_url = http://127.0.0.1:8000`, `mail.driver = log`.

## Ограничения

- Корзина хранится в браузере (заказы — в БД).
- Онлайн-оплаты нет: способы оплаты — это варианты при получении/по счёту, которые выбирает клиент.
- Нет подтверждения смены e-mail и 2FA для админки (доступ по логину/паролю и лимитам).
- Один администратор по умолчанию; при необходимости можно добавить запись в `admins` вручную.
